# 運用ガイド (経理・案件オーナー向け)

このドキュメントは、システム導入後の月次運用手順を説明します。Claude Codeはこの内容を元に、別途Word化された運用マニュアルを作成してください。

## 月次の業務フロー

### 月初 (1日)

**自動実行 (9:00):** システムが対象月の請求行を6件自動作成。各オーナーにSlack通知。

**オーナー作業 (1日〜3営業日):**

1. スプレッドシートを開く
2. メニュー「請求管理 → オーナー入力フォームを開く」
3. 自分の担当案件が表示される
4. 各案件について以下のいずれかを実行:
   - **固定額の場合**: 「前月コピー」ボタンで前月明細を複製
   - **変動額の場合**: 単価×数量を入力 (例: アポ単価 × 件数)
5. 「提出」ボタンで承認待ちステータスへ

### 月末2-3日前

**経理(みく)作業:**

1. メニュー「請求管理 → 承認画面を開く」
2. 入力済の6件を確認
3. 異常値 (前月比 ±20%超) は赤警告される → オーナーに確認
4. 問題なければ「承認」、訂正必要なら「差戻」
5. 全件承認後、「請求管理 → 一括発行・送付」を実行

### 一括発行・送付実行時 (自動)

ボタンを押すと自動で以下が実行される:

1. freeeで請求書6件作成 (PDFはfreee側に保存)
2. 同時にfreeeで取引(deal)作成 → 売掛金/売上高 の仕訳が立つ
3. メール送付対象クライアントには自動でメール送信 (CC/BCC込み)
4. メール以外(現状エピックベース等)は担当者にSlack通知 → 手動送付

### 月末〜翌月初

**自動消込 (固定額3社):** GMOあおぞら銀行から入金されると、freeeが自動で売掛金を消し込む。

**消込チェック (月初5日 自動):** システムが前月の全請求の消込状況をチェック。未消込があればSlack警告。

**みく作業:**

- 警告が出たら freee画面で対応する取引を確認
- 振込人名がズレている場合は手動マッチング
- 振込手数料が引かれている場合は差額仕訳を追加

## 例外対応マニュアル

### ケース1: 入力フォームに自分の案件が表示されない

→ クライアントマスタの `案件オーナー` 列を確認。あなたのアカウント名と一致しているか確認。一致していない場合は山岡に修正依頼。

### ケース2: 単価を間違えて提出してしまった

→ 「請求管理 → 承認画面」を経理に開いてもらい、「差戻」で戻してもらう。再度入力フォームから提出。

### ケース3: freee請求書発行でエラーが出た

→ Slack `#billing-notify` チャンネルに詳細が投稿される。よくあるエラー:

| エラー内容 | 対応 |
|---|---|
| `partner_id が見つかりません` | freeeで取引先が削除されている可能性。「freee同期」を実行 |
| `tax_code が不正` | クライアントマスタの設定値を確認 |
| `template_id が不正` | freeeで請求書テンプレートが変更されたか削除された可能性。山岡に連絡 |

### ケース4: メール送付エラー

→ Toアドレスが不正な可能性。クライアントマスタの送付先を確認・修正してから、対象請求行のステータスを `発行済` に手動で戻し、再度「一括発行・送付」を実行 (発行済の場合はメール送付のみ実行される)。

### ケース5: 振込人名がズレて自動消込されない

例: 「カ）アシオット」で入金された場合、freeeが自動で「アシオット株式会社」と紐付けられないことがある。

→ freee画面で手動マッチング:
1. freee「自動で経理」画面を開く
2. 該当の入金データを開く
3. 「+ 売掛金消込」をクリック → 対応する請求書を選択

これを一度実行すると、freeeが学習して次回以降は自動マッチングされるようになる。

### ケース6: 振込手数料が引かれて入金額がズレる

例: 請求550,000円に対して、550,000 - 手数料1,650 = 548,350円で入金された場合。

→ freee画面で消込時に「振込手数料」項目を追加:
1. 該当の入金 (548,350円) を開く
2. 「+ 売掛金消込」で対象請求 (550,000円) を選択
3. 差額1,650円を「支払手数料」として登録

## クライアント追加・停止の手順

### 新規クライアント追加 (3分)

事前準備: freee画面で取引先を登録しておく。

1. メニュー「請求管理 → クライアント管理」
2. 「追加」タブ
3. ドロップダウンから新規取引先を選択 (freee側に登録した名前で表示される)
4. 案件オーナーを選択
5. 送付方法を選択
6. 送付先メール (To) を入力
7. CC があれば入力
8. 件名テンプレを入力 (例: `{年}/{月} カスタマーサクセス支援`)
9. 月額固定金額を入力 (固定額の場合のみ。変動制は空欄)
10. 「クライアントを追加」

→ 翌月1日の月初トリガーから、このクライアントの請求行が自動作成されるようになる。

### クライアント停止 (1分)

1. メニュー「請求管理 → クライアント管理」
2. 「停止/再開」タブ
3. 停止対象を選択
4. 停止理由を入力
5. 「停止する」

→ 翌月以降、請求行が自動作成されなくなる。過去のデータは全て残る。

### クライアント再開

「停止/再開」タブから停止中クライアントを選択 → 「再開する」。

## freee OAuth 設定 (初期セットアップ時のみ)

GASからfreee APIを使うために、freee開発者アプリの登録とOAuth認証が必要です。

### Step 1: freee 開発者アプリ登録

1. https://app.secure.freee.co.jp/developers/applications にアクセス
2. 「新規アプリケーション作成」をクリック
3. 以下を設定:
   - アプリ名: `bizmote 請求書管理システム`
   - アプリ種別: `プライベートアプリ`
   - コールバックURL: GAS側のSCRIPT_IDを使ったURL (Claude Code が後で指定)
   - アクセス可能な事業所: bizmote株式会社のみ
   - スコープ: `read`, `write`
4. 「保存」をクリック
5. 表示された Client ID と Client Secret をメモ

### Step 2: GAS側に登録

1. GASエディタを開く
2. 「プロジェクト設定」 → 「スクリプト プロパティ」
3. 以下を追加:
   - `FREEE_CLIENT_ID`: Step 1 で取得した Client ID
   - `FREEE_CLIENT_SECRET`: Step 1 で取得した Client Secret

### Step 3: 認可フローを実行

1. メニュー「請求管理 → 開発者メニュー → freee OAuth 認証」を実行
2. ポップアップで認可URL が表示される
3. URL をクリックしてfreeeにログイン → 認可
4. 認可コードがコールバック経由で取得される
5. アクセストークン・リフレッシュトークンが自動で Properties Service に保存される

### Step 4: 接続確認

メニュー「請求管理 → 開発者メニュー → freee接続テスト」 → bizmote株式会社の情報が表示されればOK。

## トラブルシューティング

### freeeアクセストークンが無効になった

→ メニュー「freeeトークン手動リフレッシュ」を実行。それでも失敗する場合は再認可。

### スプレッドシートが重い

→ `03_請求一覧` シートの行数が多くなっている可能性。年度終わりに別シート(アーカイブ)に移動する運用を検討。

### 一括発行が途中で止まった

→ ステータスが `承認済` のままの行を確認。ログ (Slack `#billing-notify`) で失敗理由を確認 → 個別対応 → 再実行。
